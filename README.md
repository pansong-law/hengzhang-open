# 衡账 · Mac 本地版

个人案件与律师费管理工具。支持诉讼、法律顾问和专项项目，无须登录，可离线使用。

## 使用

支持 macOS 13 或更高版本，通用版兼容 Apple 芯片与 Intel Mac。打开打包后的“衡账.app”，即可新建案件或导入 Excel 台账。首次启动是空台账，不包含真实案件或人员名单。

- 案件台账：客户、当事人、案由、阶段、服务范围、进展及结案记录。
- 律师费：签约金额、累计开票、累计收款、未付及开票未付金额；逐笔收款与期初已收款分开记录。开票未付金额可在新建、编辑和 Excel 模板填写，留空按累计开票减累计已收款计算，最低为零；手填后以登记值为准，清空可恢复自动计算。
- 提醒：手动标记待开票，按顾问服务期限显示到期提示。完成提醒不自动登记开票或收款。
- 顾问续签：创建独立案件，继承客户和约定信息，开票、收款及流水归零。
- Excel：在“导入台账”下载模板，预览后导入；相同内部案号合并非空字段，无案号时新建。“导出当前筛选”导出可见记录，按类型分工作表。重新导入时仅读取第一张工作表。
- 工作台集中展示费用汇总、按业务类型统计、客户未付金额及提醒，不提供按承办律师统计。
- 承办、协办律师为自由填写的姓名，不关联账号或权限。
- 开发者：潘松律师，主页 https://aifalv.vip/，可从设置与备份页或应用菜单打开。

## 数据与备份

默认数据目录：~/Library/Application Support/Hengzhang Local/。数据库及备份与 App 分开，替换 App 后会保留。可在“设置与备份”打开该目录。

启动时生成备份；使用中每隔至少 30 分钟，在下一次保存前生成备份。导入、删除和恢复前另做备份。保留最近 30 份。本机备份用于防误操作或文件损坏；设备丢失或硬盘故障需通过另一设备上的备份恢复。

“导出备份”保存带完整性校验的 JSON 文件，包含所有案件、收款流水、进展和提醒。恢复前显示内容数量，确认后整体替换当前数据，并先保留恢复前备份。Excel 台账不包含全部历史记录，不能代替完整备份。

如数据库无法读取，App 启动时提供选择完整备份恢复的入口；原损坏文件保留于数据目录的 recovery 子目录。

台账可通过 Excel 导入、导出进行交换。历史进展、收款流水和提醒通过完整备份保存和恢复。

## 开发和验证

需要 Node.js 22 或更高版本。打包后的 App 自带运行环境，使用者无需安装 Node.js。

- npm ci：安装开发依赖。
- npm start：启动桌面应用。
- npm run dev:server：仅启动浏览器开发服务。
- npm test：数据、金额、导入、备份恢复及本机访问测试，使用临时目录。
- npm run test:desktop：真实 Electron 窗口中的业务与文件操作验证，使用临时目录。
- npm run pack:mac：构建 Mac 通用版 .app。
- npm run dist:mac：生成 Mac 通用版 DMG。

打包目录仅包含 desktop、server.js、lib、public 和应用图标，不包含测试数据、备份、开发脚本、密钥或历史多人版代码。

正式对外分发需要使用开发者自己的 Apple Developer ID 签名并公证。默认构建采用本地 ad-hoc 签名，未使用 Apple Developer ID，未进行公证，不能视为已通过 Apple 公证。

## 软件更新

从 1.0.3 起，App 启动后自动检查新版本，持续运行时每 6 小时检查一次，也可在“设置与备份”或“衡账”菜单中手动检查。顶部提示不会打断正在填写的案件；可忽略当前版本，下一版仍会提醒。自动检查可关闭，手动检查仍可使用。

检查只向 GitHub 读取本项目版本信息，不上传案件。断网、限流或授权失败会显示检查失败，不会误报已是最新版。仅正式发布且通用版 DMG 已上传完成的版本才触发提醒。点击“前往下载页”使用系统浏览器打开本项目的 Release；下载后退出衡账并替换 App，数据保存在独立目录。当前功能不自动替换正在运行的 App。

更新来源：pansong-law/hengzhang-mac，当前为私有仓库。私有测试阶段需要仓库读取权限：已登录本机 GitHub CLI 时自动复用其授权，令牌仅在内存中用于本仓库请求；也可在“私有版本访问”中填写独立的只读访问令牌，由 macOS 安全存储加密后保存在本机。凭据不进入案件备份或源码。打开私有下载页还需浏览器中有仓库访问权限。仓库公开后，检查更新自动使用匿名访问，无须改动 App。

## 发布下一版

源码与私有安装包发布到独立仓库 pansong-law/hengzhang-mac，不携带原多人版的 Git 历史。开发者需要已登录且有仓库写入权限的 GitHub CLI。

1. 完成修改后，用 npm version 新版本号 --no-git-tag-version 提升版本。
2. 运行 npm test、npm run dist:mac；使用实际打包 App 完成 npm run test:desktop 验证。
3. 在系统临时目录准备更新说明 Markdown 文件，运行 npm run release:preview 核对版本、仓库状态及源码范围。
4. 运行 npm run release -- --notes /绝对路径/更新说明.md。脚本检查签名及打包文件与源码一致后，将干净的单机版代码快照提交到新仓库，创建版本标签，上传 DMG 和 SHA-256 校验文件并校验远端安装包。

私有阶段脚本要求仓库保持私有。以后主动将仓库公开后，发布命令需额外指定 --allow-public。已有版本不能覆盖，需要提升版本号。1.0.2 及更早版本需先手动安装一次 1.0.3 或更高版本，才能收到 App 内提醒。
